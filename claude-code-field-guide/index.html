06:43 · Onboarding

A repo you've never seen

You've inherited a Python data pipeline. You need to understand it fast, not read it line by line.

Start with claude in the project directory, then run /init. Claude scans the repository and proposes a CLAUDE.md file at the project root. This file becomes a standing brief that loads into every future session. It lives at ./CLAUDE.md (or ./.claude/CLAUDE.md) and is committed with the team. Personal notes that you don't want shared go in ./CLAUDE.local.md, which is automatically gitignored.

Next, mention specific files using the @ prefix. Typing @src/dispatcher.py with autocomplete pulls that file into context and lets you ask "what calls this and what does it call?" The Explore agent — which runs on Haiku and is read-only — handles this kind of recon quickly and cheaply.

To see what you've loaded so far, use /context. It renders a grid of files, memory entries, and tool definitions currently in your context window, so you can spot waste. When the conversation drifts, /compact analyze the ingestion path rewrites it around that focus and drops unrelated content.

Facts that apply across all your projects — like a style convention you always follow — belong in ~/.claude/CLAUDE.md. Open it with /memory, which also lets you toggle auto-memory and inspect what's currently loaded. Auto-memory lives at ~/.claude/projects/<proj>/memory/MEMORY.md and auto-loads the first 25 KB or 200 lines at session start. Set CLAUDE_CODE_DISABLE_AUTO_MEMORY to turn it off.

22:48 · Planning a refactor

Plan first, edit later

You're about to touch the auth layer in a React + Node monorepo — sessions, JWT refresh, the whole concern. Before any file gets written, you want a plan.

Press ⇧ Tab to cycle permission modes: default → acceptEdits → plan. Stop at plan. In plan mode, Claude can think and propose but can't modify files. You can also start in plan mode directly with --permission-mode plan, or jump in from the prompt using /plan untangle the JWT refresh race. The plan gets saved as a Markdown file named after your prompt — for example fix-auth-race-snug-otter.md.

For deep work, increase thinking. ⌥ T toggles extended thinking on. Adding the word ultrathink to your prompt maxes effort for that turn. For finer control, /effort opens an interactive slider — low, medium, high, xhigh, max. You can also set MAX_THINKING_TOKENS as an env var to cap globally (set to 0 to disable thinking entirely). The showThinkingSummaries setting shows thinking inline; it's off by default now.

When the plan comes back and step 3 looks wrong, you have two options. /branch alt-no-redis forks the conversation to pursue an alternative (alias: /fork). Or use Esc Esc — the rewind gesture, equivalent to /rewind or /undo. Rewind walks back both the conversation and the code checkpoint.

Once the plan is right, switch out of plan mode with ⇧ Tab again to enter acceptEdits mode — Claude writes files without prompting, but network calls and dangerous commands still require confirmation. Use /diff to inspect pending changes interactively, and Ctrl O to toggle the transcript viewer for verbose tool usage. /permissions shows recent denials with a Retry button.

Sat 09:12 · Parallelism

Run many features in parallel

You have a Saturday and a backlog of eight small refactors, each independent. Serially this takes hours. With git worktrees, it takes minutes.

A git worktree is a separate checkout of the same repo on a different branch, in a different folder, sharing the same .git object store. Claude can edit eight worktrees in parallel without collisions, and you review each as a clean diff.

Launch a single isolated session with --worktree feat-rate-limit. For batch work, /batch takes a list of independent tasks and automatically creates worktrees — it scales to 30 parallel agents. Each task runs as a Claude subagent. In agent frontmatter, isolation: worktree tells the runtime to give the agent its own checkout, and sparsePaths limits which directories get checked out.

Your status line can show which worktree you're operating on. Set workspace.git_worktree in the status line JSON, and pair it with refreshInterval to re-run the script every N seconds.

While agents run, Ctrl B backgrounds tasks and Ctrl T toggles the task list. To invoke a specific named subagent in the foreground, mention it with @agent-name. To resume an agent where it left off, use SendMessage (this replaces the older resume verb). If two agents go wrong, Ctrl X Ctrl K (press twice to confirm) kills all background agents. The worktrees stay on disk for review.

Agent frontmatter has several useful keys: background: true runs in background by default; maxTurns caps the agentic loop; initialPrompt auto-submits the first turn; memory: user|project|local controls which memory the agent reads. CLAUDE_CODE_FORK_SUBAGENT=1 enables forked subagents on external builds.

14:00 · Code review

Reviewing pull requests

You're on call this week with ten PRs in review. Different PRs need different review approaches.

For a small PR you want to read carefully, /review 4231 pulls it locally and lets you discuss it conversationally — ask questions, request refactors, dispute earlier reviewer comments. The diff stays local.

For a large PR you can't read end to end, /ultrareview 4231 kicks off a cloud-based review with multiple parallel agents, each scrutinizing a different concern: correctness, security, style, tests. The CLI equivalent for headless use is claude ultrareview pr/4231. It accepts a PR number, branch, or path.

For a dependency bump or anything security-sensitive, /security-review scans the diff for vulnerabilities — eval'd input, secret patterns, version pinning issues. It's a triage layer, not a full SAST tool.

When the PR context lives across platforms, --from-pr loads context directly from GitHub, GitLab, Bitbucket, or GitHub Enterprise. Combined with claude -p (headless) and JSON output, you can build a review queue.

If a bug is hard to reproduce, switch from "find the bug" to debugging. /debug intermittent 502 from /api/checkout orchestrates a troubleshooting workflow — it asks for the debug log, proposes hypotheses, suggests instrumentation. For debug-level logging of Claude Code itself, use --debug with an optional filter.

Two more reviewing tools: /simplify runs three parallel agents that each propose simplifications of a chosen file or function, so you get three opinions in one turn. /insights analyzes your sessions report — useful monthly to see what you're actually spending time on.

Sun 16:30 · Configuration

Owning the configuration

Settings come in tiers, and each tier overrides the one above it. Knowing where things live is the difference between fluent use and constant frustration.

~/.claude/settings.json is your user-level — the defaults you want everywhere. .claude/settings.json in a repo is project-shared (committed). .claude/settings.local.json is project-local (gitignored). ~/.claude.json holds OAuth tokens, MCP server lists, and session state — you rarely touch this by hand. .mcp.json at the repo root lists MCP servers the team should have. On managed Linux/WSL fleets, IT can drop policy fragments into managed-settings.d/.

Use /config key value to write through to user settings without editing JSON by hand. /config with no args shows everything in scope.

Visual settings matter when you spend hours in the tool. /theme opens a picker that includes named custom themes and an "Auto (match terminal)" option. /color sets just the prompt-bar color — useful for telling sessions apart. /keybindings remaps shortcuts (helpful when your terminal already uses Ctrl T). /scroll-speed adjusts pager scroll. Run /terminal-setup once on a new machine to configure terminal-side keybindings — it ensures keys like ⌥ T actually toggle thinking instead of inserting a literal Greek letter.

Rules are conditional memory. Put project rules in .claude/rules/*.md and personal rules in ~/.claude/rules/*.md. A paths: key in the frontmatter (YAML list of globs) makes a rule load only when matching files are in scope. Inside any CLAUDE.md you can use @path/to/file to import — one source of truth composed into different contexts.

Wed 11:00 · Custom skills

Writing a custom skill

You realize you've done the same task on three consecutive Wednesdays. The fourth time, you write a skill so Claude can do it for you.

A skill is a directory: .claude/skills/<name>/ for project skills, ~/.claude/skills/<name>/ for personal. Inside is a SKILL.md file with YAML frontmatter and instructions. The description field is critical — it's how Claude decides when to invoke the skill automatically. Write descriptions like trigger conditions: "Use this when the user asks for the weekly error summary."

Other frontmatter keys control behavior. allowed-tools pre-approves tools so the skill doesn't pause for permission prompts. model overrides the model — your weekly summary should run on Haiku, not Opus. effort overrides effort level. paths: [globs] scopes the skill to certain files. context: fork runs the skill in a subagent, so its work doesn't pollute the main conversation.

The body of SKILL.md is instructions for Claude. You can interpolate variables: $ARGUMENTS is whatever the user typed after the skill name, ${CLAUDE_SKILL_DIR} is the absolute path to the skill's own directory (useful when shipping helper scripts), and ${CLAUDE_EFFORT} is the current effort level. The !`command` syntax runs a shell command at skill load and injects its stdout into the prompt — for example !`date -u` gives Claude the current date.

If you ship a plugin with binaries (a Bash helper, a Python script), put them in plugin bin/. The Bash tool finds them on PATH during the skill run. /skills lists available skills. /agents lists registered subagents. The built-in Skill tool also discovers built-in slash commands like /init, /review, and /security-review.

For zero-trust environments where you don't want skills running arbitrary shell commands, set disableSkillShellExec in settings to disable the !`cmd` injection.

Thu 13:30 · MCP

Connecting MCP servers

Claude Code, on its own, sees your filesystem and runs shell commands. To give it access to external systems — Linear, Sentry, internal docs, Postgres — you connect MCP servers. Each MCP server exposes a set of tools that Claude can call.

Three transports cover the common cases. --transport http is the recommended remote transport — your company hosts an MCP server somewhere, and Claude connects to it. --transport stdio is for a local process — useful when the server is a binary on your machine. --transport sse uses server-sent events and is mostly for legacy remote setups. Use HTTP for new servers.

Each server is registered in one of three scopes. Local is in your ~/.claude.json and applies only to you. Project is in .mcp.json at the repo root — committed and shared. User is the same file as Local but with a global flag, applying across every project. Pick scope by audience: team-wide goes in project, personal goes in local or user.

To manage servers interactively, use /mcp. To list from the CLI, claude mcp list. Once configured, set alwaysLoad: true in the server config to keep it connected across all sessions; without it, the server is lazy-loaded on demand.

Two practical limits to know. Some MCP tools return a lot of text. The default per-tool text threshold is generous, but you can raise it up to 500K characters by setting _meta["anthropic/maxResultSizeChars"] in the tool response (or maxResultSizeChars on the server). Slow servers can wedge a session — set MCP_TIMEOUT in milliseconds to bound startup time.

Hooks can call MCP tools directly. A hook step with type: "mcp_tool" invokes a server tool without involving Claude's deliberation. Useful for guardrails — for example, automatically running a schema-lint MCP tool against any proposed migration diff.

Fri 09:00 · Automation

Hooks and scheduled loops

Hooks and loops automate different things. Hooks are reactive — when X happens, do Y. Loops are proactive — every N minutes, do Z.

Manage hooks with /hooks. A simple post-edit hook might run eslint --fix after Claude writes a *.ts file. Conditional hooks are more interesting: the if key takes permission-rule syntax, the same DSL used by the permissions system. So a hook can fire only when Claude touches files matching production/*.yaml, ask for confirmation, and otherwise block.

A few hook-config keys matter in production setups. continueOnBlock lets the conversation continue even after a hook blocks a tool call, instead of halting entirely. hooks: "defer" is for headless runs — pause the session, persist state, resume later when conditions are met. The PermissionDenied hook is the specific trigger for when auto-mode classifies an action as denied; you can route those to Slack for human review. autoMode.hard_deny lists actions that auto-mode never approves — typical examples include rm -rf / or force-pushes to main.

The Monitor tool streams events from background scripts, so a hook can react to external events — for example, firing a conversation when CI emits a structured deploy-failure event.

Loops are scheduled tasks. /loop 15m check the SRE dashboard and summarize new alerts runs that prompt every 15 minutes. The alias /proactive describes it accurately: acting on a schedule, without prompting. Use loops for hourly digests, midnight cleanups, or scheduled reminders.

Two safety controls. CLAUDE_CODE_DISABLE_CRON halts all scheduled tasks at the next tick — useful before handing your laptop to IT or before a long flight. Every scheduled invocation gets a CLAUDE_CODE_SESSION_ID in its environment, which is your trace handle for correlating logs into observability tools.

Mon 03:00 · Headless & CI

Claude as a command-line tool

The interactive version of Claude Code has a headless sibling — useful in CI, cron jobs, and any pipeline where you want intelligence without a conversation.

The basic shape: claude -p "summarize today's failed tests". The -p flag means print — Claude runs once, writes its answer to stdout, exits. For machine consumption, use --output-format json or --output-format stream-json. The streaming variant emits JSON objects line-by-line as Claude produces them, so downstream tools can parse incrementally.

You can pipe input in: cat error.log | claude -p "extract unique stack traces". This makes Claude a Unix-style filter — you compose it with grep, jq, and xargs.

Cost discipline matters in unattended runs. --max-budget-usd 5 halts the run when it hits the ceiling. Pair with --effort low for jobs where you want answers without deliberation. The /claude-api command loads the API and SDK reference into context so you can write orchestration code with Claude's help.

The environment variable surface matters in CI. ANTHROPIC_API_KEY is the obvious one. ANTHROPIC_MODEL overrides the default model. ANTHROPIC_BASE_URL redirects to a proxy or gateway — essential when your company routes model traffic through an internal layer. ANTHROPIC_BETAS sends additional beta headers for preview features. ANTHROPIC_CUSTOM_MODEL_OPTION adds a custom entry to the /model picker (for example, a fine-tuned model your team maintains).

Less obvious but useful: API_TIMEOUT_MS defaults to 600,000 (ten minutes) and can be raised. CLAUDECODE=1 is set automatically so your shell scripts can detect when they're running inside Claude Code. CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN opts out of the fullscreen renderer if your terminal doesn't handle it well.

For long-running jobs that hit the same system prompt repeatedly, ENABLE_PROMPT_CACHING_1H opts into the 1-hour prompt cache TTL — a big win. FORCE_PROMPT_CACHING_5M forces the shorter 5-minute TTL. If caching is unexpectedly off, the DISABLE_PROMPT_CACHING* family emits a startup warning. You can also continue a CLI session in the desktop app with /desktop, or open a web view with --remote.

Anytime · Day-to-day

Day-to-day commands

Smaller commands and shortcuts you'll use constantly, grouped for reference.

Recovery. Ctrl C cancels the current input or generation. Ctrl D exits the session. Ctrl L clears the input and forces a full redraw — fixes a glitched terminal. Ctrl U clears the input buffer; Ctrl Y restores it. Ctrl G opens the current input in your editor (same as Ctrl X Ctrl E) — useful for multi-paragraph prompts. Ctrl R reverse-searches prompt history.

Composition. \ Enter inserts a newline without sending. For Vim users, v enters visual-character mode and V enters visual-line mode inside the prompt.

Prefixes. / is a slash command, ! runs a direct bash command without involving Claude, and @ mentions a file with autocomplete. Typing !git status is faster than asking Claude to run it.

Session navigation. /clear wipes the conversation. /copy 3 copies the third-to-last response. /recap summarizes the session when you return to it. /export dumps the conversation to disk. /resume "memory-leak-investigation" reopens a named session. /rename renames the current one. /focus toggles a focus view inside fullscreen. /goal write the migration script and validate it sets a completion goal — Claude continues until met, with a live progress overlay.

Side questions. /btw what does grep -P mean? asks a question without adding to the main conversation. The answer doesn't consume your context budget.

Model and effort. ⌥ P switches model in place; ⌥ O toggles fast mode (lower latency, lower depth); /fast on is the explicit form; /model opens the picker, with left and right arrows adjusting effort inside the picker. For multiple models, set modelOverrides in settings to map picker labels to custom IDs.

Usage and limits. /usage shows token usage, cost, and cache breakdown (it replaces the older /cost and /stats). /extra-usage appears when you're rate-limited. The 1M context window is available on Opus 4.6 (Max, Team, and Enterprise plans); CLAUDE_CODE_DISABLE_1M_CONTEXT opts out per machine.

Voice. /voice toggles push-to-talk dictation. Hold Space to record, release to send. Twenty languages are supported.

Diagnostics. /doctor diagnoses your installation. /insights analyzes your sessions report. /help lists everything. /feedback (alias /bug) sends a report.

Housekeeping. claude update pulls the latest version. claude plugin prune removes unused plugins. claude project purge ./old-repo deletes all Claude Code state for a path. claude auth login handles sign-in, with --sso and --console variants. DISABLE_UPDATES blocks all update paths. CLAUDE_CODE_PACKAGE_MANAGER_AUTO_UPDATE enables auto-upgrade via Homebrew or WinGet.
