LLM Model & Runtime Map

A technically honest way to place the major ideas around LLMs and current AI systems. Think of this as a map, not a conveyor belt: model classes, adaptation, information handling, and execution are connected but distinct.

↳

The useful correction: a foundation model can also be a frontier model; fine-tuning is an optional adaptation step; inference is what happens when a model is run.

The map at a glance.

These four areas explain different parts of an AI system. Keeping them separate prevents a helpful simplification from becoming a misleading one.

01 / Model class

Foundation + frontier

What the model is and where its capability sits relative to the state of the art.

02 / Adaptation

Prompts + fine-tuning

How behavior is guided or how the model’s weights are specialized.

03 / Runtime

Context + inference

How information reaches the model and how it produces an output in use.

The core four.

These are the ideas at the center of the original explanation, refined into their precise roles.

01

Foundation model

A broadly pretrained base model.

It learns general patterns from large and varied data, then provides a base for many downstream uses. It is not a framework in the software-library sense, although it can play a similarly foundational role in an AI stack.

02

Frontier model

A model at the current capability boundary.

“Frontier” describes position and capability, not a mandatory next stage. A frontier model may also be a foundation model; the two labels answer different questions.

03

Fine-tuning

Adapting model weights with specialized data.

Fine-tuning turns a general model into a more targeted one for a domain or task. It changes the weights; prompt engineering does not.

04

Inference

Running a model to produce an output.

Inference is the serving-time execution step: a user or application supplies input, the fixed model snapshot processes it, and the system returns a result.

Not a pipeline: Foundation → frontier → fine-tuning → inference is a useful story only if treated as a rough orientation. In practice, frontier is a capability label, fine-tuning is optional, and inference is the runtime operation.

Information and adaptation.

The model’s weights are only one part of what shapes an answer. These tools change what the model sees or how it is specialized.

Data & context

How information reaches the model.

Tokens / tokenization

Text is split into the units a model reads and processes—often pieces of words, not whole words.

Context window

The maximum amount of tokenized information the model can process at one time: the working space for a prompt.

RAG

Retrieval-Augmented Generation: retrieve relevant private or current information before generating an answer.

Adaptation

How behavior is guided or weights are changed.

Prompt engineering

Structure instructions, examples, and constraints without changing the model’s weights.

LoRA / QLoRA

Parameter-efficient fine-tuning: freeze the base model and train a small additional set of weights.

Quantization

Reduce numerical precision to make a model smaller or faster. It is compression, not fine-tuning.

Execution & behavior

What happens when the system is running.

Agents / agentic workflows

A model is given tools and a loop so it can take steps, inspect results, and pursue a larger goal.

Temperature

An inference setting that influences randomness: lower tends to be more deterministic, higher more varied.

Hallucination

A confident, coherent output that is factually wrong or fabricated.
